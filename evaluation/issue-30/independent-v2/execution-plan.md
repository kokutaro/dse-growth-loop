## 実行・採点・時間計測

1. 承認済み資料とラベルを不変manifestに固定する。専用ダミーscopeで投影し、通常人物パイプラインと正本照合を使う。
2. サービス経路で全24問を`all`／対象指定の2条件で実行する。通常SPAの既存JWTでも同じ全24問・2条件を確認し、実応答IDと実際に表示した各欄の順序を保存する。機密JWTは証跡へ含めない。
3. 人物／事例の各欄の先頭5件を採点する。従来の混在先頭5件も併記する。明示対象外の推薦は対象指定時の違反として数え、`all`の別欄表示とは区別する。正解なしでは全表示欄に推薦がないことを確認する。
4. ウォーム計測は起動済み状態で全24問を測り、APIリクエスト開始から本文受信完了と、送信からUI表示完了を別々に記録する。キャッシュ利用・分類呼出し・RU・AI使用量も記録し、分類キャッシュなしの初回HTTP48件と反復24件を分けて集計する。
5. coldは人物・事例・正解なしの代表3問。各回で実replica 0、サーバーキャッシュなしを確認してから測定し、失敗・timeoutも含めて別報告する。HTTPタイミングをサービス内部時間で代用しない。

合格条件は一次Recall人物／事例各90%以上、指定した複数職歴・副業務例の正解全件取得、各欄Hit@5／Precision@5各90%以上、正解なし誤推薦0、根拠ID・実送信原文整合100%。warm HTTP p95は15秒以下。unknown手動移行とLLMの全件不適合を別集計する。未達・欠測・中断は合格にしない。
