# 技能辞書への候補提案：Choice v1

## 製品経路

カタログ画面の明示照会から、認証API、辞書サービス、既存AiService/Jev、実行ゲート・設定済み予算・監査、提案保存まで接続する。operator/member、元資料閲覧権限、候補ETag、現在の辞書版/ETagを照会前と結果保存前に確認する。別名・統合・新規登録の承認、人物経験、gold、検索、通知は更新しない。

`skill-catalogue-choice-v1` は閲覧可能で原文と共有範囲が完全に等しいactive概念をすべて使用する。種別を事前に隠さず実務/知識/資格を提示し、不整合な種別への選択は要確認にする。文字top3による絞込みや完全一致のAI省略は新方式の前には置かない。候補の原文・根拠ID・役割・対象・作業・条件と、全対象項目の名前・定義・境界・別名を渡す。送信番号と元の辞書IDの対応はサーバーで保持する。同一の定義・境界だけを共通値へまとめ、欠けたフィールドは共通値全文を参照すると明記する。上位domainが同じだけでは同じ技能にしない。

Choiceは既存ID、`none_of_the_above`、`insufficient_evidence`の単一選択。既存IDは対応候補、noneは新規候補の確認、uncertain/競合/エラーは要確認とする。空の対象辞書はAIなしの新規候補で、登録確定でも本人経験の認定でもない。複数の独立技能や根拠不足は保留を選ぶよう質問するが、この製品版の実AI品質は今回未測定である。

## 上限と状態

公式Choiceは最大255択なので、技能は最大253＋2状態。通常の辞書作成上限は既存の200概念を維持する。上限を超える入力は辞書を部分送信せず理由付き要確認にする。既存の入力・出力・停止・同時実行・予算枠を変更しない。

`skill-choice-wire-v1` で全技能をc000等の固定番号に対応させ、特殊2状態はそのまま送る。固定順序と全ID集合を検証し、対応表hashと版を監査へ保存する。モデルは承認済みIDを生成せず、応答の全番号を検証してサーバーで元のIDへ戻す。名称はcriteriaに一度だけ置き、辞書行は明示した列順の配列とする。同じ名称の別名はnull参照、同じ定義・境界は共通全文参照とし、復元テストで全フィールド一致を確認する。この参照nullは業務のunknown/null状態とは別の通信表現である。原文・条件・否定の切捨てや技能の間引きはしない。

前回の実験用50技能辞書（ローカルテストのscopeのみdemoへ置換）と短い合成原文では、入力見積り11,224→7,943、出力見積り2,610となり、通常の入力8,000・出力3,000枠で認証・AI実行管理・提案保存まで通ることをモックで確認した。前者はUTF-8バイト＋256、後者は固定応答形と数値最大32バイト/値＋256からの保守的見積りであり実token計測ではない。32バイトを超える数値表現は丸め直さず応答不正として要確認にする。通常の実応答サイズ・実usage上限の検査も維持する。Jevにmax-output指定はないため、枠を超える応答を送信前に完全保証するものではない。

この出力見積りだけなら技能59＋2状態まで3,000内だが、入力は定義や原文の長さに依存する。50技能を常に処理できる保証ではなく、上記原文の入力余裕は57だけである。独自定義や長文なら全量を保ったまま `AI_INPUTLIMIT` / `AI_OUTPUTLIMIT` の要確認にする。予約は見積り値へ縮小せず、既存の設定全枠8,000/3,000を既存ゲート・設定済み課金台帳で扱う。台帳無効の既存構成では再導入せず、停止・同時実行・許可・監査を継続する。設定拡大・外部API・追加分割は今回0。

通信結果不明やdispatchingの再送は禁止し、既存のフェンスやAIガードも解除しない。送信前拒否とprovider側の不確定結果を区別する。失敗や空集合を一致・新規技能確定へ変換しない。

## 丸めを含む応答検証

[公式Choice](https://docs.typesafe.ai/primitives/choice)は合計1、[公式SDK詳細](https://docs.typesafe.ai/sdk/python/api/types/responses)は近似的に1と説明している。SDK0.7.5は保存された合計0.99の応答を未補正で受理した。公式は具体的な許容差や固定の丸め桁を規定していない。

`choice-probabilities-v2` の数値境界は本実装の保守的な互換方針である。生の値を変更・再正規化せず、まず合計誤差1e-6以下を受理する。それ以外は、全値が浮動小数の誤差1e-12以内で共通の小数2〜6桁グリッド上にある場合だけ、観測桁をdとして丸め区間 `[max(0,p−0.5×10^-d), min(1,p+0.5×10^-d)]` が真の合計1を含むか確認する。合計誤差の許容は `min(0.02, 候補数×0.5×10^-d)` で上限2ポイント。候補数が増えて許容が過大になることを防ぐ独自の上限で、公式の±0.02規定ではない。52択の0.019×52=0.988も3桁丸めとして扱えるが、丸め区間で合計1を説明できない分布は拒否する。高精度の値を2桁へ丸め直す処理はしない。

個別のNaN/Infinity/負数/1超過、未知・重複・欠落キー、選択が最大値でない応答、confidence範囲異常、大きな合計異常は引き続き拒否する。受理理由・合計・許容幅・観測桁・未正規化を監査と提案へ保存する。confidenceは合計検査にも本人経験認定にも使用しない。確率・confidence・順位差に自動承認の閾値は設けない。

## 入力表現と互換性

前の入力修正 `skill-semantic-input-v2` を維持する。比較JSONの二重文字列化をなくし、完全に同じ引用は対応する根拠IDの全文を参照する。部分引用・末尾の否定や条件・全根拠は切り捨てない。送信専用JSONはUTF-8を使い、HTMLに埋め込まない。送信と同じシリアライザーのバイト数＋256で従来の入力枠を検査する。これは実token数ではない。

提案ID・idempotency・キャッシュには方式/プロンプト版、入力版、確率検証版・wire版、原文fingerprint、辞書版/snapshot hash、候補集合を含める。同じ方式の同じ条件は別キーでも再実行しない。辞書版や方式の違う結果は流用しない。旧noul提案は `previousProposals` として原文権限を再確認して読み取り専用表示する。過去の正順/逆順/min/0.8は新Choiceの確率・confidenceと別であり、Choiceの閾値にしない。古い記録の削除や一括書換えは不要。コードを戻す際も新旧の提案記録は保持する。

## 検証の意味

ローカルの非公開証跡では保存済み5応答を未補正で再読した。公開リポジトリには評価辞書・評価入力・生応答を含めず、一般化した5つの丸め応答形式、入力サイズの境界ケース、全52択、none/uncertain、複合入力、空辞書、版変更、権限失効、長文、API失敗・同時再送、既存画面/API/監査/状態保存をモックで検証する。追加実APIは0。本実装のテスト成功と実AIの意味品質は別である。前回の合成18例のSDK再読18/18は小規模な開発者期待との比較で、一般精度や未見精度の保証ではない。
