# 技能辞書への意味候補提案 v1

## 現在の状態

既存カタログ画面から認証付きAPI、既存AiService/IDecisionProviderのJev経路へローカル接続した。未公開の実装であり、本番に配信していない。ブラウザ検証では外部通信できないテスト専用transportを使い、実際の認証判定・元資料検証・AI実行ゲート・監査・永続化を通す。実APIの意味判定品質は未検証、追加APIは0回。
## 製品接続と保存境界

候補レビューから既存技能の候補照会を明示的に実行する。operator・元資料の閲覧権限、候補ETag、現在の辞書版/ETagを確認し、実行意図を保存してfenceを解放する。既存AiService/IDecisionProviderのJev経路で判定し、元資料と辞書版を再確認して提案だけを保存する。AiService自身の認証、SourceGuard、AI実行ゲート、設定済み予算・利用量監査を維持する。新規の課金台帳や承認ゲートは追加しない。

既存の人の承認操作を呼ばず、別名・統合・新規登録・人物経験・検索投影・評価goldを更新しない。候補原文、引用、条件、役割、実務/知識/資格は変更しない。本人経験の適格性と辞書概念の提案は別の判断である。

## 候補検索と判定

- 固定版のactive概念から共有範囲が完全に等しく種別も同じものを対象とする。文字2-gramの重なりで最大3概念へ絞る。大分類IDは使わない。検索順位は同等性の判定ではない。
- 既存の完全一致・登録済み別名はAIなしの候補として区別する。
- 意味比較は定義、境界、別名、対象、作業、条件、種別と原文上の主体・役割の制限をJevへ提示する。モデルへID選択を依頼せず、サーバーで固定したindexに対する2問だけを使う。返値のキー・確率・存在するID・版・現在の権限を検証する。
- 正順/逆順の最小値が0.8以上なら既存技能の候補。複数が満たす場合は要確認。一方だけ高い、未知応答、API失敗、版変更は要確認。
- 適合する辞書が空なら新規候補。全適合概念を調べ、両方向とも0.2以下なら新規候補として人へ渡す。0.2は不一致確定や校正済み確率ではなく、保守的な表示振分けの固定値。0.8の同等性基準を下げるものではない。
- 辞書が3概念を超え未確認項目がある場合、一致なしを新規確定へ変換しない。0.2～0.8の曖昧さも要確認とする。どの状態も人の承認を必要とする。

## 再送・キャッシュと失敗

actor・候補の元資料fingerprint・辞書snapshot hash・判定policy版から永続的な提案IDを作る。既存IdempotencyExecutorとETag条件付きでpreparedを作成し、dispatchingへの移行を一度だけ許す。同じキーだけでなく、別キーでも同じ入力/版の推論を繰り返さない。

通信結果不明やクラッシュ後のdispatchingは自動再送しない。既存のAIガードを解除しない。成功/失敗の記録と元の版を保持し、権限失効後はキャッシュも表示しない。モデル・設定を直した後の同じ入力の手動再評価機能は今回未対応で、現版では元資料・辞書版またはpolicy版が変わらない限り記録を再利用する。

## 検証範囲

従来120件から調整せず、別の合成17ケースを実行前に固定した。期待値は開発用に作成したもので人確認済み意味正解ではない。モックスコアの単体/サービス/契約テストは権限、再送、状態、情報保持を確認する。Jevの日本語同等性精度や閾値の校正は検証しない。既存120件の再評価、実API照会、公開・配信、本番辞書更新は行わない。

`GET /skill-candidates/{id}/suggestion?version=N` は保存結果だけを読む。`POST /skill-candidates/{id}/suggest` は候補If-Match・Idempotency-Key・辞書版/ETagを要求し、現在のoperator/memberと元資料を再確認する。利用者指定の辞書IDや自由なモデル入力は受け付けない。画面の比較ボタンは比較先選択のみで、既存の承認操作と分離している。結果不明時の同一キー再送や保存状態の再読込は課金を重複させない。

通常のAI設定は変更しない。AccountingMode=Disabledでは既存の単一実行ゲートを利用し、既存環境でLedgerモードが設定されている場合だけ既存の予算制限に従う。廃止した台帳や承認ゲートを復活させる設定変更はない。固定合成スコアによるテストはJevの実測精度を意味しない。
