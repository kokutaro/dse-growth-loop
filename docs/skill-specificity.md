# 技能候補の具体性と未承認の正規化案

## 概要

抽出時に対象・目的・条件を落とさず、人が原文と照合できる候補を残す。短縮された保存応答をコードで原文に書き戻して、抽出品質が改善したことにはしない。

## 抽出と原文の関係

- `raw` は技能を支持する最小限かつ十分な原文の連続部分とし、行為だけの短い句より、対象・目的・条件を含む節や箇条書きを優先する。無関係な隣接業務を含めない。
- 100文字の既存上限を維持する。十分な連続部分が収まらない場合は、原文の正確なアンカーと全文引用を保持して `uncertain` とし、人の確認に戻すようモデルに指示する。コードは意味を補完・分割しない。
- 経験・知識・否定・希望・他者実績の区別、出典ID、全セル引用、ACL、版照合は従来どおり。抽出モデルが指示に従う品質は別途実AI評価が必要。

## Choiceと過去データ

`normalizationCandidate` を未承認の参考案としてChoice入力に加える。原文・引用・辞書の定義や境界を上書きする根拠にはしない。選択肢、質問、確率検証、人の承認境界は変更しない。未承認案が原文より具体的でも、その内容を実績や辞書へ自動登録しない。

新しい抽出プロンプトはセル版v2／一般文脈版v3、Choice方針はv3とし、古い結果のキャッシュと区別する。保存済みセル引用の契約v1と技能結果v2／原文整合ガードv1は維持する。旧Choice v1/v2提案は履歴として読め、既存の原文・候補・検索・使用量は変更しない。新しい抽出には明示的な世代作成と独立した見積・予算が必要。

## 検証と制約

モックと保存応答による回帰では、短縮済みrawが変更されないこと、全文引用と元の状態が残ること、未承認案の欠落／不適切な内容でも原文・知識区分・辞書境界が保持されることを確認する。実AIの改善率や一般精度は未測定。

実験用辞書に人が定めた技能定義がなく「完全な別名一致のみ」という共通境界しかない場合、意味的に近いIDを確定正解とは扱えない。誤対応の調査ではモデルの確率と理由を混同せず、期待ラベルの妥当性も人が確認する。結果に合わせた辞書や正解の変更は行わない。
