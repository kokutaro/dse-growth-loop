# 本人紐付け・権限・公開契約

## ログイン主体と架空人物

Entra JWTの署名・issuer・audience・有効期限・委任scopeを検証し、許可済み`tid + oid`をサーバーの`IdentityBinding`で`principalId`と架空`personId`へ対応付ける。メール・表示名で照合しない。Bindingは業務文書とは別の運用設定に置き、一般API・検索投影・AI・会話へ送らない。本仕様のoid例は架空UUID。実oidはgitへ保存しない。

同tenantの有効なBindingはoidとpersonIdについてそれぞれ一意。複数テスト主体は別の架空人物に固定し、クライアントが人物IDを選ぶimpersonationは提供しない。運用者も本人に成り代わって確認しない。ローカルテスト主体はDevelopment専用で、実JWTにデモ用ヘッダーを混在させない。

roleは`member/publisher/operator/analyst`。本人・課題所有者・参加者は役割名ではなく、Bindingと正本から毎回導く関係。ownerIdだけで任意の資料の読取を許さない。運用者roleも全本文閲覧権ではない。サービス主体には当該Jobの入力・出力だけを委任し、モデル出力の「権限」や資料中の命令で範囲を広げない。

## 共有候補と三段階の正本照合

非公開資料は **現在の参加者一人ひとりに読取権限がある場合だけ** 共有候補になる。参加者の権限の和集合を使わない。チャットへの自動AI投稿はさらに公開済みKnowledgeに限定する。個人の検索結果をそのまま参加者へ配信しない。

1. **AI入力前**：候補IDをサーバーで解決。tenant、scope、元資料とKnowledgeの公開状態、activeVersion、accessVersion、分析許可版を照合。会話用途ではSessionの参加者集合とmembershipVersionも確認。情報取得に失敗した候補は送信しない。
2. **画面表示前**：検索結果・根拠・会話内引用・Opportunityを取得するたびに同じ正本を再照合。古い投影・キャッシュの本文は返さない。撤回した引用は本文/タイトルを隠し「公開が取り消されたため表示できません」と返す。すでに端末へ配信した文字列の回収は保証しない。
3. **投稿確定前**：AI生成後、入力スナップショットのsourceVersion/accessVersionと現在の正本、Sessionの版・全参加者・AI停止状態・会話openを比較。変化があれば生成を破棄してJobをneeds_reviewまたはcancelledにし、自動で無制限に再生成しない。重複キー`sourceId + sourceVersion + sessionId`と最新Session ETagを保存時に検査する。

正本照合は候補を作った古いスナップショットではなく最新の認可経路を通す。変更応答後の読取にはセッショントークン引継ぎ等でread-your-writesを満たす。別コンテナの読取と投稿の間は原子的ではないため、#5/#13では失効更新と投稿を協調させるアクセス版のフェンスを実装・競合試験する。失効処理中や版不一致は公開配信しない。保存済み投稿にもsourceSnapshotsを持たせ、配信時・再取得時に必ず再照合する。単なる「直前にGETした」だけで競合を解消したとは扱わない。

AI入力がすでに外部へ渡った後の撤回で過去の入力を取り消したとは主張しない。保存・配信されていない生成結果を破棄し、今後の再利用を止める。SignalRイベントはIDと連番のみを送信し、本文取得を認可経路へ戻す。

## 公開・分析の暫定方針

初期知識公開は参加者全員の確認を要する。要約版、公開先scope、参加者集合を固定し、どれかが変更されたら確認と分析許可を消去してdraftへ戻す。publisherの具体的な割当は未承認で、未設定なら公開APIは403。ダミーテストでroleを設定することは実運用の任命ではない。

分析は明示許可済み要約のみ。Challengeは所有者が現在版の課題要約に許可を付与する。Knowledgeは参加者全員が現在の公開要約版に分析利用を許可した後、`analysisConsent=granted`と`consentedVersion`を確定する。個々の分析確認は公開確認とは別の`analysisConfirmations`に主体・版・scope・時刻を保持し、Knowledgeと同一更新で確定する。未完了はnot_grantedのまま。Knowledgeの`confirm`（公開確認）だけでは分析許可にならない。誰か一人の撤回でrevoked、consentedVersion=null、analysisConfirmations=[]にし、分析結果の表示にも伝播させる。

Opportunity入力は公開・許可を満たすChallenge/Knowledgeのsummaryと最小メタデータだけ。私的な会話本文、未公開下書き、Feedback本文、IdentityBindingは送らない。結果には入力版とaccessVersionを残し、集計は独立したchallengeIdとdepartmentIdで重複排除する。分析許可が撤回された要約に依存する既存結果は表示を停止して再計算待ちとする。
