# 候補から育てる共通技能辞書 v1

固定カタログを最初に網羅しない。初期状態は辞書版0・承認済み概念なし。既存の根拠付き抽出結果を取り込み、承認済み版に対応する別名があればIDへ対応し、なければ「未登録」にする。カタログ外は抽出誤りではない。

## 今回の最小経路

`/skill-dictionary.html` で、閲覧可能な既存実績・知識IDを指定して収集する。AIは再実行しない。通常の `SpecificSkillRules.Assess` と `SourceGuard` で引用・現行文書版・権限を再検証し、元表現、原文、根拠ID、対象、条件、主体、関与、実務/知識/参照/資格を保持する。引用不整合など既存の隔離候補は辞書へ流さず、収集状態を「保留」とする。

最初の版では明示操作による収集を採用する。通常の抽出・検索・queueへ自動書込みを追加しない。内部的な未登録候補の蓄積とレビューまでを縦断し、自動収集の常駐処理や辞書IDによる検索置換は未対応。

## 人が行う判断

|判断|辞書と候補の変化|
|---|---|
|新規登録|安定ID、標準名、定義、含む/含めない範囲を作り、版を進める|
|既存技能の別名|その候補の表現・種別・対象・条件を承認済み別名へ追加する。既存の同じ別名なら辞書版を無駄に進めない|
|既存技能を統合|その候補が対応している統合元を、比較先の既存技能へ統合する。旧ID・別名・導入版を残し、redirectIdで追跡する|
|技能ではない|候補をnot_skillにする。辞書の概念削除や人物の実績の訂正にはしない|
|保留|候補をdeferredにし、理由を残す。判断不能を該当なしに変換しない|

各判断は人の理由と承認者、前/後の辞書版、候補と根拠のfingerprintを履歴へ残す。AIの正規化案は未承認表示だけであり、承認処理は呼ばない。新規・別名・統合は同じ閲覧スコープ内、種別の互換がある場合に限定する。同じ上位分類や旧domain IDでは対応・統合しない。

ID対応は、承認済み別名をNFKC・前後空白除去・小文字化した表記と、種別・対象・条件集合の一致だけを使用する。意味類似による自動ID付与は行わない。[意味候補提案](skill-semantic-proposals.md)を別経路で示し、承認は人が行う。旧抽出器にある意味的別名も自動輸入しない。役割と主体は候補側に残し、IDが一致しても本人経験や熟練度を認定しない。

対応付けと別名の一意性は、共有スコープ集合が完全一致する範囲で扱う。一部だけ重なる別スコープのIDを間接的に返さない。共有範囲をまたぐ辞書の共通化・統合は今回未対応であり、権限の拡張で解決しない。

## 保存と境界

既存catalogコンテナに辞書用4種のレコードを追加する（意味候補は別途skillMatchProposalに保存）。`skillCandidate`、`skillDictionaryHead`、`skillDictionaryVersion`、`skillDictionaryReview`。リソースや権限の追加は不要。版ごとのスナップショットはcreate-only、headと候補はETag条件付き。承認の辞書更新・候補更新・履歴・再送receiptは同一パーティションの原子バッチで保存する。

レビューは既存operator権限を現在のAuthorityProviderで再確認する。さらに元の経験・文書への閲覧権限、現行版、根拠を再確認する。operatorであっても私的経験の自己閲覧境界は越えない。現状の権限で中央の全社員経験をレビューできるようにはしていない。権限付与・認証設定は変更しない。辞書概念のスコープは候補元と同一にし、この機能で共有範囲を広げない。

候補は文書のアクセス版や原文・実績版が変わると再確認が必要。閲覧できない候補のIDや原文は一覧へ出さない。履歴・固定版プレビューでも現時点の根拠閲覧条件を要求する。変更された原文は再収集し、以前の監査レコードは削除しない。

同じ収集の再送は元のキーで重複を防ぎ、別キーで再収集しても同じ根拠・要素の候補を二重作成しない。承認の応答が不明なら同じキー・本文・ETagで再送する。候補版か辞書版が古ければ412として、画面は再読込と人の選び直しへ戻る。receiptを返す前にも現在の権限と根拠を確認する。

## 固定版プレビューと評価

指定した辞書版と対象候補で再分類する読み取り専用プレビューを提供する。旧IDの統合前の版も保持する。業務レコード・検索投影・通知・評価goldを変更しない。辞書の登録は人物経験の認定でも、既存タグの一括取消でもない。

今回の検査は仮データでのID対応・根拠整合性・権限・状態遷移を別々に検証する。新たな人確認済みID正解は作らず、旧自由記述120件の精度数値と直接比較しない。実AIの再実行・費用を伴う評価は行わない。

## ローカル検証と現段階の上限

- `dotnet test tests/Dse.Tests`：既存回帰と辞書の契約検査。
- `npm --prefix web run test:e2e:dictionary`：localhostだけのテスト用ホストで、架空operator・メモリ保存・実HTTP APIとブラウザを通す。製品の認証を置き換えず、テスト用権限を本番へ付与しない。
- `tests/Dse.SkillDictionaryBrowserHost` はloopbackの検証専用で通常サービスへ配信しない。通常APIのDemo利用者は辞書operatorにはならず、403を確認する。
- 実運用相当のEntraログインやAzure Cosmos上の承認競合は未検証。ローカル結果を本番検証としない。
- v1の処理上限は200概念、概念当たり別名40、候補履歴50、収集一回90候補、一覧/プレビュー50件。超過時は明示エラーで部分保存・黙った切捨てをしない。大規模化や概念の名称/定義改訂、却下取り消し、スコープをまたぐ統合は未対応。

本変更はローカルのみ。push・PR・マージ・本番配信には通常の別途レビューを要する。

## 通常デモ画面からの技能ID検索

`validation.html` の「探し方」で「承認済み技能」を選び、辞書版を明示して技能名と「知識の記載／実務経験の候補」を選択できる。辞書レビュー画面の「この辞書版で資料を探す」からも進める。操作には既存のoperator権限が必要で、一般利用者の権限を拡大しない。

`POST /api/v1/skill-dictionary/search` は指定した承認済み辞書版と現在の候補・原文根拠を読み取り時に結び付ける。原文・共有範囲・現在の認可・候補fingerprintを既存ガードで確認し、同じtenant fenceを応答の直列化まで保持する。辞書版以外は過去時点へ戻さず、撤回・根拠変更・閲覧範囲外の引用は返さない。

- registered／alias／matched／mergedの候補を固定版で再照合し、選択した知識・経験区分だけを返す。保留・未承認・不明な根拠を承認済み技能へ自動昇格させない。
- 統合前の版は旧ID、統合後の版は統合先IDで照合する。指定版でinactiveなIDを最新版の別IDへ自動変換しない。根拠と監査の状態は現在値を使う。
- 結果は資料の記載として表示し、知識の記載から人物の実務経験や熟練度を推定しない。管理画面専用フラグ付きの候補は通常検索へ混ぜない。このフラグは実データ／架空データの区別ではなく、既存の利用範囲の境界である。
- 辞書版・技能ID・区分はJSON入力でも必須。上限は表示100件、走査100ページ（1ページ50件）。空の閲覧結果が続く場合も走査上限を適用し、超過は422で部分成功を返さない。既存の検索RU予算も維持する。
- AI・再順位付け・再収集・投影更新・辞書変更・監査追記は行わない。版や条件を変えると画面の古い結果を消し、画面切替後の遅延応答も表示しない。

技能ID検索は通常デモ画面に接続済みだが、従来の語・分類条件との複合検索、自然文AI検索・再順位付けへの統合、技能IDの検索投影への永続化は未実装。[架空2資料での検証記録](validation-results/20261107-ordinary-skill-search.md)を参照。
