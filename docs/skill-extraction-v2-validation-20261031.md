# 原文文脈による技能抽出 v2 の限定検証

同じ合成職務経歴書3冊・6案件・19業務で、XLSX機械読取から新規Foundry抽出、Jev Choice、候補収集まで一巡した。入力・開発者期待値・辞書50技能・モデルは前回から固定した。人承認済み正解や未見評価ではない。

| 指標 | 今回 | 前回 |
|---|---|---|
| 原文業務の意味保持（参考診断） | full19/19 | full18、partial1 |
| 通常候補の業務意味（参考診断） | full18、引用保留1 | full15、partial2、曖昧1、保留1 |
| 既存IDの参考期待 | 2/4 | 1/4 |
| 機械的要素化の誤変換 | 0 | 2 |

新規rawは56項目（経験19・知識35・未実施等2）。54候補と引用保留通知2件を追跡できる。候補数の増加は知識の追加を含み、精度改善率ではない。主副担当等の分類は要求せず、共同作業も関与を理由に保留しない。案件の役割・原文情報は残す。

実APIはFoundry6、Jev54（分野6・技能Choice48）、合計60。受理された経験候補18/18をChoiceまで実行した。知識候補6件は事前の呼出上限で未判定のまま保持し、正解や空集合に変換していない。全呼出し終端・fence/gate解放を確認した。設定価格によるusage見積はUSD0.027625556、事前最大USD0.06500352。請求額とAzure計算・保存・preview費用は未確認。

残る課題は、引用見出しの置換や途中省略による原文不一致2件、DB移行の既存ID未対応、正規化候補が原文の範囲を狭める例。引用保留の業務はID採点4件の分母に残した。コードは意味を再判定しないため、AIの文脈誤解を形式検査だけで保証できない。抽出prompt・後処理・Choice入力を同時変更しており、一要因の効果や安定した一般精度を示す実験ではない。

製品の同じDomain/Infrastructureを既存validation Job内の一時CLIで実行し、業務永続化先は隔離した。通常HTTP・Worker lease・実環境の認証付きoperator承認・本番検索は未検証。元の自己PRセルと読取位置のずれは入力を変えず残し、未読取部分をモデルの品質評価へ混ぜていない。本番の人物・辞書・gold・検索・通知の更新は行っていない。

ローカル検証は.NET 1,011、契約32、scripts331、認証7、評価器5、関連ブラウザ32、型検査・Release build・Bicep compile・評価器smokeが通過。ブラウザはモックであり、実AI品質とは別検査。

旧v1候補は残すが、新文脈判定へ自動変換しない。再抽出まで具体技能専用検索の対象外となり、一般原文・語句検索は維持する。専用検索の表記正規化はUnicode・前後空白・大小文字のみで、固定の同義語置換はしない。公開前に移行運用を確認する必要がある。自動有料再抽出や本番設定変更は追加していない。
