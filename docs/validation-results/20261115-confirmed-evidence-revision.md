# 本人確認済み資料の通常訂正と根拠の引継ぎ

Issue #16。架空資料の本人確認後、同じ資料へ作業経験の段落を追加すると、既存の本人確認済み項目が旧版の根拠を保持して後続の投影が `SOURCE_REVOKED` になる不具合を修正した。

## 引継ぎの条件

本文と期間が変わらない本人確認済み・本人訂正済み項目について、同一資料・人物・所有者・tenant・scope、旧版の検証済み引用、新版の現行根拠を正本で照合し、新版の根拠へ引き継ぐ。履歴読取は同一性の確認にだけ使用し、旧引用を検索やAIで再び利用可能にはしない。

変わった内容、削除された根拠、別資料、撤回、権限の失効は自動引継ぎしない。履歴を含む全読取は計画のETag検査へ加わり、競合時には投影と監査の公開を止める。引継ぎ前後の根拠は同じコミットの監査に記録し、同一計画の再構築で監査を増やさない。新たな段落は以前の本人確認を継承しない。

## 検証

`ConfirmedEvidenceRevisionTests` の32ケースで、本人確認・本人訂正の維持、別資料、本文・期間変更、削除、所有・tenant・scope・人物・権限・撤回、履歴の不正、ETag競合、監査と再構築を検証する。試験はメモリ正本・Mock AIを使う。

2026-11-15の隔離したAzure受入では、2つの実JWTから通常画面で架空Wordの本人確認と同一資料の版更新を行い、Azure Queue→Worker→人物投影で両資料の旧本文の確認状態と新しい根拠が引き継がれた。新しい経験文は未確認の別項目、元の技術名一覧は知識のまま維持した。上流AIはMockであり、実AIの抽出品質の検証ではない。共有サービスや既存データ・認証・同意は変更していない。

同じ受入の二者相談・評価・要約の双方同意・公開は3件成功したが、同系列の実AI事業分析と判断は未実施。この修正によって業務全工程の実AI受入が完了したとは扱わない。
