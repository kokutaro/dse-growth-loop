## 再開手順

1. API・Workerを停止したまま、既存Jobを推論停止・live opt-in無効で`--weekly-budget-initialize`または台帳読み取りモードにする。既存週の初期化は冪等で、利用カウンターを初期値へ戻さない。週が変われば新週承認設定の初期化を明示実行する。未完了予約0、停止理由なし、段階全体の予算・token上界が残量内と確認し、Jobを元設定に戻す。
2. 操作可能な認証ブラウザーとsanitized HAR記録を準備する。ロック待ちの間はAPIを展開しない。元テンプレートをアクセス制限された場所に保存し、復帰を時間内に実行するwatchdogを準備する。
3. 既存`dse-api`のみ上記digestで一時展開し、既存テストアカウントの`Auth__Grants__0__ScopeIds__0`を専用scopeへ一時置換する。人物15、入力16,000／出力3,000、試行1・同時実行1、日次450万token、週2,000円・162円/USD・非runtime予約1,200円・call上限1,680を維持する。API/Worker/Jobの他の公開範囲・identity・ロール・RBACを変更しない。
4. SPAを読み込んだwarm状態で、承認済み24問の原文を自然文・target=`all`で各1回送信する。手動条件を足さない。422の対象外2問もHTTP状態・時間・UI表示を保存する。pendingの検索を再送しない。表示欄内の順位・検索runIdとHTTP応答を照合する。
5. APIをdeactivateして実レプリカ0を待ち、必要なら停止中に台帳を再確認する。既に読み込んだSPAを保持し、GETで温めずにAPIをactivate、実レプリカ0の証跡を取った直後に最初の自然文検索を送る。固定計画の3問をこの方式で測り、cold値をwarm SLOに混ぜない。
6. API・Jobを元イメージ・環境・公開scope・資源・scale・引数へ戻し、deactivate後の実レプリカ0・実行中Job0と台帳を確認する。失敗・時刻欠落のJobはtimeout900秒を累計へ計上する。
