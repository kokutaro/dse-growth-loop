# 原文の文脈を保つ技能抽出 v2

## 方針

スキルシートの担当業務は本人の経験を記載したものとしてAIが読む。主担当・副担当・共同・補助の関与分類は要求せず、それを理由に候補を保留しない。案件の役割欄・原文引用は削除しない。

AIは文脈から具体技能を抽出し、`basis` を `experience` / `knowledge` / `qualification` / `not_experience` / `uncertain` として返す。明示的な未実施、希望・計画だけ、知識の列挙、他者の実績を本人の実施経験へ変換しない。計画を作る実作業と、計画された活動の実施も区別する。これは主副担当の分類ではない。

コードは形式・件数上限、根拠ID、引用の原文一致、元表現が引用にあること、対象断片との所属を検証する。「と」「を」等による分割、動作・対象の生成、条件・否定・主体のキーワード推定は行わない。AIの1項目を、表記を書き換えず1候補として保持する。正規化候補は承認済み技能IDではない。Unicode・前後空白・大小文字の検索正規化は意味を変更しない範囲で残す。

引用が原文と一致していても、その引用をAIが正しく解釈した保証にはならない。AIが否定を見落とした場合、形式検証だけでは検出できない。`basis` はAIの未確認出力であり、人の承認・熟練度の証明ではない。この限界は実AI評価で測る。

## 版と既存データ

- 新しい抽出は `specific-skills-v2`、後処理は `source-integrity-v1`、候補表示は `skill-elements-v2`。新規AI出力に `participation` はない。
- v1の `participation` は過去記録の読取り用として保存するが、表示上の主副分類や新方式の経験認定へ流用しない。旧候補は消さず `legacy_extraction_requires_refresh` として保持する。新方式の新規抽出が必要であり、自動有料再実行は行わない。
- 新版のハッシュ・guard版により古い提案はstaleとなり、古い引用や承認をそのまま使わない。現在のACL・削除／撤回・根拠版の照合と再収集、冪等性、人の辞書承認は従来どおり。
- Choice提案は `skill-catalogue-choice-v2`。根拠・抽出文脈を渡し、主副担当の違いを技能ID選択条件にしない。旧Choice v1は履歴でChoiceとして表示し、noulスコアへ誤変換しない。既存辞書の定義・境界・権限・確率検証・費用ゲートは変更しない。
- 技能名の固定対応（C#等の暗黙の概念ID付与）は行わず、承認済み辞書で照合する。旧スキル検索タグは新方式へ自動移行しない。v1の具体技能は、新規抽出まで具体技能専用の検索条件にヒットしない。一般の原文・語句検索は維持する。この移行影響があるため、旧版候補の保持と再抽出の運用を確認してから公開を判断する。

## 検証の位置付け

HK形式の合成3文書・6案件・19業務と保存済み応答で、過剰な関与保留がなくなること、`担当者を調査`・`手元を使えるよう`が生成されないこと、根拠IDの誤りが引き続き隔離されることをローカル再生する。旧応答からの再生は新プロンプトの実AI精度ではない。入力・期待値・過去の評価証跡は変更しない。

新しいプロンプトの `basis` 判定、複合技能の分け方、目的・対象の保持、明示的な未実施・知識・他者実績の扱いには、別途承認された新規実AI評価が必要。初回のローカル実装では有料AI・Azure Job・push・PR・配信を実施していない。その後に承認された新規実AI評価は [限定検証結果](skill-extraction-v2-validation-20261031.md) を参照。保存応答の再生と新規実測は別の結果として保存する。
